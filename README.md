# llm-wiki

A second brain for software engineers that an AI agent keeps for you.

`llm-wiki` is a complete, opinionated implementation of Andrej Karpathy's [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) pattern: a folder of interlinked markdown that a coding agent (Claude Code, Cursor, or any agent with file tools) **ingests into, answers from, and lints**, while you keep judgment and provenance. It ships three parts that work together:

| Part | What it is |
|---|---|
| `skill/` | A Claude Code skill (and `cursor/` rule) that teaches the agent the three workflows and the hard rules |
| `vault-template/` | An empty vault with the schema, folder layout, and a seed page, ready to `git init` |
| `agent/` | The `wiki` CLI: ranks pages for a query, keeps the generated index current, migrates an existing vault |

The pitch in one line: **the bottleneck of a knowledge base is bookkeeping, not thinking.** Give the bookkeeping to the agent, and post-mortems stop evaporating.

## How it feels in practice

```
you:    ingest this Slack thread about the retry bug
agent:  → sources/retry-storm-thread-2026-05-20.md
        → entities/backoff-policy.md (updated, +1 source)
        → entities/retry-storm.md (new stub)
        → _meta/log/2026-05.md (+1 line)
        → git commit (explicit paths)

you:    how long do we cache events when the uplink is down?
agent:  wiki search → top hits [[offline-cache]] § Retention, [[retention-policy]]
        → reads both, follows their links → answers citing both, saves
        queries/offline-cache-retention.md because it will be asked again

you:    lint the vault
agent:  3 orphan pages, 2 broken links, 1 contradiction between
        [[backoff-policy]] and [[retry-storm]] — fix?  (waits for you)
```

## Quick start

Needs bash, git, and Python 3.11+. The CLI is optional; the skill works without it.

```bash
git clone https://github.com/Mograbi/llm-wiki.git
cd llm-wiki
./install.sh ~/wiki            # vault path of your choice
```

Clone somewhere permanent. `install.sh` symlinks into the checkout rather than copying, so moving or deleting it later breaks the CLI and the skill.

`install.sh` will:

1. copy `vault-template/` to the path you give, `git init` it, and commit,
2. write that path to `~/.config/llm-wiki/vault` so the skill and CLI find it,
3. install the `wiki` CLI into a virtualenv and symlink it to `~/.local/bin/wiki` (skipped with a warning if Python is older than 3.11),
4. generate the first `_meta/index.md`,
5. symlink the skill into `~/.claude/skills/llm-wiki` (Claude Code) and print the Cursor instructions.

Pointing it at a vault that already exists leaves the contents alone and tells you to run `wiki init`, which migrates it safely: a hand-written index is archived, not overwritten. Pointing it at a non-empty directory that is not a vault is refused, so it can never git-commit a folder you did not mean it to.

Then open your agent and say: *"ingest this"* with a link, a file, or a pasted conversation.

No API keys are needed beyond the agent you already use. The CLI has one dependency and makes no network calls except to your own local Ollama, if you enable it. Threat model in [SECURITY.md](SECURITY.md). Semantic search is an opt-in: install [Ollama](https://ollama.com/download), run `ollama pull nomic-embed-text`, then `wiki reindex`. Without it, `wiki search` runs full-text BM25 ranking alone and says so.

## The three workflows

- **Ingest**: a source becomes a summary page, the concept pages it touches are created or updated, everything is cross-linked both ways, one log line is appended, one commit is made.
- **Query**: the agent runs `wiki search` to find candidate pages, reads the best ones, follows the wikilink graph, and answers with `[[citations]]` to pages that exist. Answers worth keeping are saved to `queries/`.
- **Lint**: orphans, stale entities, broken links, missing project tags, contradictions, index drift. Read-only until you say fix. Lint is the agent's judgment over the vault, not a checker; there is no `wiki lint`.

Two supporting workflows, **Log today** (reconcile the day's commits with the log) and **Killed-session recovery** (a fresh session finds what the dead one never filed), are described in [docs/workflows.md](docs/workflows.md).

## The rules that make it work

Every one of these came from something going wrong.

1. **The schema is authoritative and the agent reads it before every write.** Conventions drift within days otherwise.
2. **Every fact carries provenance.** Who, when, where. Half the value of a fact is knowing how much to trust it.
3. **Link only to pages that exist.** Fluent models invent plausible page names. A wiki of confident dead links is worse than none.
4. **Corrections are first-class.** Update the page, record what changed, mark the old claim superseded. The archive gets less wrong over time.
5. **The private vault and the public document are different artifacts.** Names, customers, and hosts stay in the vault. Anything that leaves is translated first. See [docs/publishing.md](docs/publishing.md).
6. **The log is the spine.** One line per action, append-only. It is how a fresh session recovers what a killed one never filed.

## The `wiki` CLI

```
wiki search "question" [-k 8] [--project TAG] [--json] [--sync]
                           # rank pages: path, best section, snippet, score
wiki reindex [--full]      # regenerate _meta/index.md; refresh embeddings if Ollama is up
wiki init                  # migrate an existing vault: git init, shard the log, generate the index
```

`wiki search` is a finder, not an oracle. It returns pages for the agent to read; there is no model in the loop, so there is nothing to hallucinate. It always runs a full-text ranker (SQLite FTS5, BM25, stemming, title weighted). With Ollama it also ranks by cosine over section-level embeddings and fuses the two lists by reciprocal rank, with each ranker's first choice guaranteed a top-3 slot, so a page both rankers like rises to the top and a rare exact token still surfaces when only full-text search can see it. The first line of its output says which mode ran (`hybrid`, `semantic`, or `lexical`) and whether coverage is partial.

The index is the one file in the vault that is generated rather than written, so the agent never has to keep a catalog by hand and a sync client can never corrupt an in-place edit of it. Design notes in [docs/agent-design.md](docs/agent-design.md).

## Repository layout

```
skill/llm-wiki/SKILL.md     Claude Code skill (the agent's instructions)
cursor/llm-wiki.mdc          Cursor project rule, same content condensed
vault-template/              Empty vault: schema, folders, seed pages
agent/                       The wiki CLI: search, generated index, vault migration (Python 3.11+, offline)
docs/                        Workflows, agent setup, publishing rules, design
install.sh                   One-shot installer
```

## Uninstall

```bash
rm ~/.local/bin/wiki ~/.claude/skills/llm-wiki
rm -rf ~/.config/llm-wiki ~/.cache/llm-wiki
```

Your vault is a plain git repository of markdown. It is yours, and nothing above touches it.
