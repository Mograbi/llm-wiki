# Vault Schema

This vault is maintained by an AI agent on the user's behalf. It follows Karpathy's "LLM Wiki" pattern: raw sources are read-only inputs, this vault is the synthesized layer.

**Agents: read this file before every write. It is authoritative over any skill or rule text.**

## Folder layout

- `_meta/` - this schema, the generated index, the append-only log shards
- `projects/` - one hub page per project or workstream
- `sources/` - one page per ingested artifact (paper, gist, video, doc, conversation, incident)
- `entities/` - evergreen concept pages (techniques, tools, systems, components)
- `queries/` - synthesized answers worth preserving
- `people/` - collaborators, contacts, authors (optional)

Subfolders inside the content folders are allowed (`sources/2026/foo.md`); the index generator recurses and skips dot-directories such as `.obsidian` and `.trash`. Prefer frontmatter and tags over deep folder trees, since wikilinks resolve by filename, not path.

## Projects

Canonical project tags. Use exactly these values in `projects:` frontmatter; edit this list when a project starts or ends.

- `example` - replace with your first project (e.g. `payments-platform`, `thesis`, `homelab`)

A page can belong to several projects. Always populate `projects:`; it is the primary filter. For finer scoping inside a project, use secondary `tags:` (e.g. `tags: [backend]`) rather than inventing project variants.

## Conventions

- **Linking**: wikilinks only, `[[Page]]`, never `[text](file.md)`. Quote them inside YAML lists.
- **Filenames**: `kebab-case.md`. Time-anchored sources (investigations, incidents, single-day logs) carry an ISO date suffix: `outage-postmortem-2026-05-20.md`. Evergreen pages carry no date; `updated:` / `ingested:` / `asked:` handle freshness.
- **Dates**: absolute ISO `YYYY-MM-DD`, never relative.
- **Tags**: lowercase, hyphenated, small vocabulary.
- **Provenance**: every claim carries who said it, when, and where. Corrections are explicit: update the page, record what changed in `last_change:`, and say "supersedes" or "corrects" in the log line.
- **Public vs private**: this vault may hold names, customers, and hosts. Anything copied out into a code repository or a public document is translated to generic operational wording first.

## Repositories

Where the agent looks for commits during the "log today" workflow. Edit to your code root; list several if your work is spread out.

```yaml
repo_root: ~/work        # e.g. ~/src, ~/dev, /Users/you/Projects
repo_depth: 3            # how many levels deep to search for .git
```

## Log

`_meta/log/YYYY-MM.md`, one shard per month, append-only, one line per action:

```
YYYY-MM-DD - ingest - [[slug]] (projects): one-line gist
YYYY-MM-DD - query  - [[slug]] (projects): one-line gist
YYYY-MM-DD - update - [[slug]] (projects): what changed and why
YYYY-MM-DD - lint   - N findings, M fixed
```
